# Agent Operating System

## Purpose
The agent operating system makes future generated apps behave like software projects, not raw static pages.

## Lifecycle
User prompt -> requirements -> user stories -> matrices -> implementation plan -> frontend/backend generation -> integration -> tests -> build -> deployment -> value score -> final report.

## Matrix Gate
Implementation is blocked until requirement, story, feature-pattern, route/RBAC, CRUD, backend-contract, state, test, and value-score matrices exist.

## UI Kit Gate
Generated web and Electron apps must use the sanctioned UI-kit cache first. New wrappers are allowed only when the matrix records the missing capability and the wrapper is app-specific.

## Backend Gate
Persistence, roles, admin screens, dashboards, reports, files, workflows, settings, and CRUD imply backend contracts, validation, auth, RBAC, tests, and generated app-local persistence.

## QA Gate
The final QA gate applies the value-score matrix and caps scores for unwired CRUD, missing backend RBAC, superficial UI-kit usage, absent tests/build, or missing final checklist.
